# AlfathPulsa theme system

The app has **light & dark modes** (`data-mode` on `<html>`) plus an accent color (`data-theme`), driven by `themeStore` (zustand, persisted). Theme attributes are applied at the **App root** so the Login and loading screens are themed too — not only inside `Layout` (which also sets them). If you add a screen rendered before `Layout`, it still gets themed via the App-root effect.

Current direction is **light-first ("Neumorphism Tajam + Lampu")**: one soft cool-gray surface (`#E4E8EF`) shared by canvas + cards; cards are raised via twin neumorphic shadows (`--neu-light` top-left, `--neu-dark` bottom-right); inputs and inner panels (`.bg-asphalt-900/40|50|60`) are inset/carved-in; borders are kept transparent/minimal; solid brand buttons (`.bg-brand-500`) get a glowing blue "lampu" shadow. Big balance nominals stay dark charcoal (not glowing) via the global `.text-white` → dark override. Dark mode is retained as a calm ambient-blue option (neumorphism is light-mode only).

All theme styling lives as **global utility-class overrides in `artifacts/alfathpulsa/src/index.css`**, NOT per-component — edit the `[data-mode='light']` / `:root:not([data-mode='light'])` blocks and the `--bg-asphalt-*` / `--brand-*` / `--neu-*` vars there. Menu service tiles are also CSS-driven now: the old per-label rainbow gradient map was removed from `ServiceIcon` (`Dashboard.tsx`); each tile just emits `.menu-tile` (one raised neumorphic surface) + `.menu-tile-icon` (single blue `--brand-500` accent), styled in index.css. All buttons get a tactile press (`:active` → carve-in inset + slight scale-down) so taps "feel alive" — the user explicitly asked for this and for the unified, de-rainbowed menu.

**Why:** the user rejected the earlier dark "glowing glass" theme and a later "Fresh Light" white-card look, then approved sharp neumorphism + glow via a canvas mockup. **How to apply:** to retune the look, edit the index.css override blocks; to restyle menu tiles, edit the `.menu-tile` / `.menu-tile-icon` rules in index.css (there is no longer any color map in `ServiceIcon`). Neumorphic effects only show over real logged-in content, so verify with the testing skill (log in with the seeded admin documented in `replit.md` → "Default login").

**Gotcha — global input shadow vs focus ring:** the light-mode `input/textarea/select` override sets `box-shadow: ... !important` for the inset look, which suppresses Tailwind's `focus:ring` (also box-shadow). A dedicated `input:focus` rule restores a visible brand focus ring — keep it if you touch the form-field overrides.

**Gotcha — fluid fonts:** `html { font-size: clamp(...) }` (plus a short-landscape `@media`) scales all rem-based Tailwind sizes (text AND spacing) so nothing looks oversized across phone/tablet/orientation. Fixed `px` sizes (`text-[10px]` etc.) do NOT scale by design.

**Persist-key gotcha:** the themeStore persist `name` is versioned (`alfath-theme-storage-v2`). Bumping it forces existing users back to defaults — and resets **both** the mode and the accent color, not just the mode. Bump it only when you intend that reset.

**Solid-blue blocks become "lampu" (light mode):** per user, NO full-color blue fills — every blue block (buttons, tabs, filter chips, icon buttons, the brand side-strip, gradient avatars) is converted to a light neumorphic surface where only the LETTERS + ring/border glow blue, lifting + glowing brighter on `:active`. Done globally in index.css by overriding `button.bg-brand-500/600`, `.bg-brand-500/600.text-white`, `.bg-brand-500.self-stretch`, and blue gradients (`from-brand-500`, `from-emerald-500`). **Gotcha:** because of the palette remap, solid `bg-emerald-500/600` renders blue too, so those selectors are included as well (a Team "Tes WhatsApp" button used `bg-emerald-500` and was initially missed). Descendant `.text-white` is recolored blue to avoid invisible white-on-light text. Red/danger (rose) blocks intentionally stay solid — they are not blue. **How to apply:** any new blue CTA should use the `bg-brand-*`/`bg-emerald-*` conventions so the global override applies automatically; avatar color cycles (Savings/Debts) were forced all-blue so no red avatar leaks in. **Lampu follows the accent**, not hardcoded blue: the converted blocks use `var(--brand-600)` for letters and `color-mix(in srgb, var(--brand-500) …%, transparent)` for ring/glow, so changing `data-theme` retints them. **Gotcha for dark mode:** `bg-brand-*` follows the accent via `--brand-*`, BUT the success/cool families (emerald/teal/green/sky/cyan) are pinned to a FIXED blue by the @theme remap — so a dark-mode rule re-points their solid 500/600 button fills to `var(--brand-500/600)`; without it, e.g. a `bg-emerald-500` button stays blue when a non-blue accent is chosen.

**Dark mode "pekat" + raised cards:** user wanted a deeper dark canvas so cards clearly "timbul". Done by darkening the dark `--bg-asphalt-*` vars + body bg (~#03050A) and adding a `[data-mode='dark'] .bg-asphalt-800` rule with a drop shadow + faint top-edge inset highlight + subtle border. **Why:** neumorphism is light-only, so dark mode needs explicit shadow/contrast (not neu tokens) to make cards pop; brightened `--text-asphalt-*` for legibility on the darker bg.

**Popups must be iOS-styled — and that includes native dialogs:** the user asked for "popup ala iOS" everywhere. Custom popups (ConfirmModal, SuccessToast, the global error banner, the theme picker) use `.ios-*` classes in index.css that adapt via `[data-mode]`; action color follows the accent via `var(--brand-600)`, destructive = iOS red. **Gotcha:** native `window.alert()`/`window.confirm()` are also popups and must NOT be left as-is — route them through the global dialog store (`src/store/dialogStore.ts`: `iosAlert`/`iosConfirm`, Promise-based) whose `<IosDialog/>` host is mounted in `main.tsx` as a sibling of `<App/>` so it works even outside the React app tree (e.g. the PWA-update prompt). **How to apply:** never add `alert/confirm`; call `iosAlert`/`iosConfirm`. `prompt()`-style native APIs that aren't dialogs (e.g. `BeforeInstallPromptEvent.prompt()`) are NOT popups — leave them. Icons on colored circles inside popups need `.ios-on-color`, never `text-white` (global light override blanks it).

**Palette harmonization (Tailwind v4 opacity-inlining gotcha):** to fold loud default hues into the calm theme, override the default color *values* statically in the `@theme` block of index.css (e.g. `--color-emerald-500: #0084FF`). **Why:** Tailwind v4 compiles solid utilities to `var(--color-x)` BUT inlines the literal oklch for opacity variants (`bg-x/10` → `color-mix(... <literal> ...)`), so overriding only the runtime var leaves all `/10`,`/20` usages unchanged — a static `@theme` value gets inlined as *your* color in every variant. Current semantic mapping: success/positive (emerald + cool hues) → brand blue; pending/warning (amber/orange/yellow) → muted gold (#AC8235); danger/negative/delete (rose/red/pink) → muted red (#BE4A52). **How to apply:** (1) the @theme remap does NOT reach hardcoded literals in components — Recharts `fill=/stroke=` props and arbitrary `shadow-[...rgba()]` glows must be edited by hand (grep `#10b981`, `rgba(16,185,129`, etc.); (2) some `[data-mode='light']` per-hue `!important` text/glow overrides also force colors and must be retargeted in lockstep; (3) for 2-series charts, use two BLUE shades (Total #0084FF vs lighter #4D9FFF) rather than a second hue. Left untouched: the opt-in `[data-theme='emerald'|'amber'|'rose']` accent presets (deliberate user choice; default accent is blue) and the committed `AUTH_SECRET` in `.replit` (changing it logs everyone out).
